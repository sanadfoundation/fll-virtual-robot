Canvas UX Prototypes

Five live variants exploring how to give the canvas more vertical room by relocating the Motors/Sensors and Position panels. Each variant runs the real simulator — click Run in the bottom dock to drive the robot and watch the values update wherever they live now.

Prototype A

Collapsible right sidebar

Stack ports + position vertically in a slim right sidebar with a pin/hide toggle. Familiar IDE pattern; preserves canvas width but eats some horizontal room.

+full vertical canvas −240px width
Prototype B

Header popover buttons

Three pill buttons in the header (Motors / Sensors / Position) open downward popovers on demand. Canvas takes the whole panel; telemetry is one click away with live activity dots on the buttons.

+full canvas, both axes click-to-inspect
Prototype C

Floating canvas HUD

Translucent panels overlaid in the canvas corners — Motors top-left, Sensors top-right, Position bottom-right. No layout space consumed; values fade slightly while the robot is moving.

+zero chrome may cover field
Prototype D

Thin status strips

Keep the bands above/below but collapse them to a single ~26 px line of inline values. Hover or click to expand back to the full chips. Smallest visual change.

+~70 px canvas height smaller type
Prototype E

Bottom-dock telemetry

Position chips slot into the bottom dock next to the speed slider. Ports collapse into one dock button that slides up a panel of chips when toggled. Canvas takes the whole panel.

+full canvas, no new chrome busier dock
Prototype F

Packing dock

Like Prototype B but the three pill buttons collapse into a single circle on demand. Click the chevron to pack; click the circle to unpack — the circle pulses green when values change while packed.

+canvas + clutter-free two-step inspect
Baseline

Current production layout

Ports band above the canvas, Position band below — what's shipped today. Use as the reference when comparing the prototypes.

How to use: Serve the repo with python3 -m http.server 8787 (PyScript needs HTTP), then visit /prototypes/. Each card opens a working variant — click Run in the bottom dock to drive the robot and watch the values update in their new home. Every variant keeps the same element IDs that simulator.js writes to, so live data flows unchanged.
