Thumbnails

Auto-captured on every Save in the editor. The image shows the mission at its start state — robot at start pose, field laid out, no trail.

Sources rail

Bundled ships with the repo. My Missions lives in localStorage. Imported comes from drag-dropped .llmission files — kept separate so the user knows what's outside content.

Star ratings

3★ at ≥ 90% of max score, 2★ at ≥ 60%, 1★ at any positive score. Nothing is ever locked — practice tool, not a gate.

Drafts

Missions saved-but-not-finished get the dashed thumbnail and a Resume editing primary action instead of Play.

Mode signal

The header's green "PLAYING" pill replaces the usual project-name input. Exit Mission takes you back to the Library.

Score updates live

Each step's condition is polled at 30 Hz. When a step completes, the check goes green, the score number ticks up, and the points pill flips amber-filled.

Hints on demand

Show hint reveals the author's hint inline with an amber side-border. v1 has no scoring penalty for using hints — practice tool first.

Locked field

In Play mode the field is read-only: obstacles, zones, and the robot's start pose come from the mission file. The user only controls their code.

3 · Editor Mode — placing the field

Full-interface replacement. The canvas becomes a drag-to-place editor. The right column hosts metadata and the step list. No code editor in this mode — Playtest button runs the mission for a quick check.

Mode switch

Header gradient flips to purple → amber and a "Editor Mode" tag replaces the logo cluster, so the user can never mistake which mode they're in.

Direct manipulation

Selected obstacle shows an amber dashed outline plus four corner handles. Drag the body to move; drag corners to resize. The robot start has a single green crosshair handle.

Live coordinates

The right side of the canvas toolbar shows the currently selected element's id and live position/size in mm — so authors can dial in exact placements when they need to.

Playtest

Clicking ▶ Playtest snapshots to a temp slot and switches to Play mode. Back-to-Editor returns to the live edit state — the temp save is just a bootstrap.

Blockly reuse

The condition workspace is a Blockly sibling — a separate toolbox with predicate blocks. The blue blocks return booleans; the amber blocks compose them (NOT / ALL of / ANY of).

Auto-populated dropdowns

The obstacle (1 ▾) and zone (Green ▾) pickers list exactly what's currently in the field editor. You can only reference things that exist.

Canvas focuses on the subject

When a step is selected, the canvas dims unrelated elements and outlines the condition's subject in amber — making the connection between the code and the world visible.

Direct serialisation

The block tree maps 1:1 to the schema's condition primitive — no JS code generation, no eval. Save writes the predicate AST straight into mission.json.

Components first

The numbers that fed the total are listed alongside the total. Kids learn what to optimise — they shouldn't have to guess why their score is what it is.

Two scoring shapes

Missions use step_sum (each completed step adds points). Obstacle courses use base − penalties (start at 100 if you finish, lose for collisions and time-over).

Personal best

Best score per (mission_id, modifier_hash) persists in localStorage. The "previously…" line nudges kids to beat their own time.

Next-mission CTA

When a mission completes, the primary action becomes "Next mission" — surfacing a curated next pick instead of dumping the user back into the library cold.
