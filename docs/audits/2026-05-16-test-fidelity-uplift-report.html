3.Bugs fixed (with audit ref)

3.1 motor_pair.move(steering) applies steering in continuous motion · audit §4.1 PROVES

js/simulator.js:1085-1101 — case 'start' now reads cmd.steering and applies (1 ± steer/100) to the wheel velocities. Before: bridge sent steering, sim dropped it. After: round-trip Python motor_pair.move(0, 50) measurably rotates the robot.

3.2 Motor encoders accumulate · audit §4.2 (canonical stub-pin) PROVES

_animateTank now writes (wheel mm / WHEEL_CIRC_MM × 360) into robot.motors[port] per step, signed. _descriptorForPair + _animateSingleMotor emit leftPort/rightPort so the integration knows which encoder to credit. getMotorSpeed now reads from a new motors_velocity map populated for the duration of motion. Before: getMotorPosition('A') === 0 forever. After: motor.absolute_position('A') reads ~180° after a 180° run.

3.3 hub.light_matrix.show_image renders · audit §4.3 PROVES

New case 'hub_image' in _execCmd dispatching to _imageToDisplay. 4 of 67 LEGO IMAGE_* constants implemented (HAPPY, SAD, HEART, ARROW_N) with int → name resolution. Unknown image renders blank (not silent no-op). Before: silent drop, robot.display unchanged. After: pixels light through the full Python → bridge → sim chain.

5.Test posture changes, side-by-side

5.1 The canonical stub-pin, flipped

Before — tests/js/sensors/accessors.test.js the day the audit was written:

test('getMotorSpeed: returns 0 for any port', () => {
  const sim = createSim();
  assert.strictEqual(sim.getMotorSpeed('A'), 0);   // enforces the bug
});

After:

test('getMotorSpeed: 0 at rest', () => {
  const sim = createSim();
  assert.strictEqual(sim.getMotorSpeed('A'), 0);
});

test('getMotorSpeed: reflects active motion velocity', () => {
  const sim = createSim();
  sim.robot.motors_velocity = { A: 500, B: -500 };
  assert.strictEqual(sim.getMotorSpeed('A'),  500);    // asserts behaviour
  assert.strictEqual(sim.getMotorSpeed('B'), -500);
});

5.2 expectedFailure: documents the gap instead of enforcing the bug

# tests/py/test_gaps.py — new class TestKnownBugsTracked

@unittest.expectedFailure
def test_runloop_until_polls_predicate(self):
    # Per LEGO docs: runloop.until(pred, timeout) awaits until pred()
    # returns truthy. Today: returns _NoopAwaitable; pred never called.
    counter = [0]
    def pred():
        counter[0] += 1
        return counter[0] >= 3
    asyncio.run(sb.runloop.until(pred, timeout=1000))
    self.assertGreaterEqual(counter[0], 3)

This test fails today (as expected). The decorator turns the expected-failure into a green suite result. The day someone implements runloop.until properly, the test starts passing and the decorator should be removed.

5.3 A real round-trip test, end-to-end

// tests/js/integration/motor-encoder.test.js
test('round-trip: motor.absolute_position reads back after the move', async () => {
  const { runUserCode, mp } = await makeRoundtrip();

  await runUserCode(`
async def main():
    await motor_pair.pair(0, port.A, port.B)
    await motor.run_for_degrees('A', 180, velocity=500)
    global _final_pos
    _final_pos = motor.absolute_position('A')
runloop.run(main())
`);

  const finalPos = mp.globals.get('_final_pos');
  assert.ok(Math.abs(finalPos - 180) < 40);
});

Every step on this path is real: the Python is the same spike_bridge.py the browser loads, the bridge sends a real js.bridgeSend call, the sim runs real _execCmd → real _animateTank → real encoder accumulation, the bridge updates _state from the JSON reply, and the assertion is on the value Python read back. The only stubbed piece is the Box2D kinematics (replaced with a kinematic integrator so motion actually happens). Everything else is production code.

6.What didn't get done, and why

  • Trapezoidal acceleration profile — audit §6.6's largest item. Real _animateTank work, not plumbing. Out of scope; tracked via the new test_acceleration_kwarg_reaches_bridge xfail.
  • color_sensor.rgbi wiring — would need _sensorState() to emit an rgb key (reflection got wired earlier; rgbi didn't). Tracked via xfail.
  • runloop.until polling — needs a real asyncio-driven loop. Tracked via xfail.
  • Continuous-motion 200 mm / 5000 mm caps (audit §4.10) — the steering fix made direction correct; the cap is unchanged. _execCmd 'start' still hands 200 to _animateTank.
  • Remaining 63 IMAGE_* patterns — additive lookup-table entries. Chain works; coverage is by row.
  • Blockly fixture-driven behaviour runner (audit §6.2) — the round-trip harness handled the Python side first. Worth a separate session.
